# Grandstream GXP1625 — validated Issabel profile

## Support status

**SUPPORTED IN LAB**

Physical model: Grandstream GXP1625  
Validated firmware: `1.0.7.70`  
Issabel: 5  
Asterisk: 18.19.0  
Endpoint Configurator package: `issabel-endpointconfig2-5.0.0-1.el8.noarch`

This support statement applies to the tested model/firmware combination only.

## Laboratory endpoint

- MAC: `C0:74:AD:E8:66:09`
- OUI required for discovery: `C0:74:AD`
- IP during validation: `192.168.1.167`
- Issabel/TFTP server: `192.168.1.10`
- Initial rollback account: `201 Fabi`
- Validated provisioned account: `202 Ashly`

No HTTP administrator password, SIP secret, SID or cookie value belongs in this file.

## Discovery

The phone was not correctly classified until OUI `C0:74:AD` was added to the Grandstream manufacturer entries in Endpoint Configurator. OUI identifies the manufacturer, not the exact model.

The physical phone's model was confirmed as GXP1625 using the management API. Issabel model ID observed during the project: 134.

## Accounts

The Issabel model defines two maximum accounts for the GXP1625. G10-19 validated Account 1.

Validated SIP P-values for Account 1 include:

- `P35` — SIP User ID.
- `P36` — Authenticate ID.
- `P34` — Authenticate Password; secret, never log it.
- `P47` — SIP Server.
- `P270` — Account Name / display label used by this integration.

The generated XML was validated only by safe predicates such as `P35=202` or secret-present, never by printing the actual secret.

## Configuration files

Issabel's legacy generator produces:

```text
/tftpboot/cfgc074ade86609
```

The integrated solution also produces:

```text
/tftpboot/cfgc074ade86609.xml
```

Both originate from the same P-value map. The XML uses the Grandstream provisioning structure and binds the configuration to the phone MAC.

The physical GXP1625 requested both filenames. The XML path was required in the successful transition from 201/Fabi to 202/Ashly.

## Provisioning transport

Validated configuration provisioning settings:

```text
P212 = 0
P237 = 192.168.1.10
```

Meaning:

- Config Upgrade Via = TFTP.
- Config Server Path = Issabel PBX.

For this firmware, the bare server IP is valid with TFTP selected. Do not require `tftp://192.168.1.10/` for this validated path.

## HTTP administrator credential

The model default HTTP password in the Issabel database did not match this physical phone. The final integration therefore uses an `endpoint_properties.http_password` override for this exact endpoint.

This is preferred over changing the model default because a model-wide change could break other GXP1625 units that still use their expected default or a different managed credential.

## Native management login

Validated request for `/cgi-bin/dologin`:

```text
POST /cgi-bin/dologin
Content-Type: application/x-www-form-urlencoded
Accept: */*
Host: <phone-ip>
Referer: http://<phone-ip>/

username=<configured-http-user>&password=<configured-http-password>
```

The body values are shown here only symbolically; never include the real password in diagnostics.

No explicit User-Agent is required by the validated minimal contract. H8L also
proved that a product-specific Issabel User-Agent is accepted, but the final
implementation omits it because it adds no compatibility value. A valid login
returns JSON success with a SID.

## Session handling

The physical phone's web UI creates `session-identity` matching the login SID. The final Issabel native path:

1. preserves safe cookie pairs returned by login,
2. synthesizes `session-identity=<SID>`,
3. sends the combined Cookie header to `/cgi-bin/api.values.post`.

The tested native POST returned:

```text
response=success
status=right
```

No actual SID or cookie value is logged.

## Endpoint Configurator behavior

The GUI/CLI configuration flow uses `endpoint.selected=1` to identify endpoints to process. `issabel-endpointconfig --applyconfig` clears that flag after execution.

Automated tests for this model must verify the exact endpoint by manufacturer, model, MAC, IP and account before setting the flag. Never select all Grandstream endpoints as a shortcut.

## Verified final result

The physical phone changed from Fabi to Ashly and Account 1 readback confirmed 202. After a real reboot, the account remained 202/Ashly.

Asterisk subsequently reported extension 202 registered `OK` from `192.168.1.167`, while extension 201 no longer used that phone IP.

G10-19H8I demonstrated the first complete no-Chromium native run. G10-19H8J retained the final request/session compatibility patch after a successful clean Endpoint Configurator run. H8L removed the unnecessary fixed User-Agent. H8M then completed two full native cycles separated by 300 seconds and retained the minimal patch.

## Known observation requiring more characterization

Two immediate repeat attempts in G10-19H8K regenerated the correct XML but reported native activation failure. A later H8K2 attempt traversed the complete login/POST path and received `success/right` without changing the final H8J contract.

Do not label the rapid-repeat failures as a specific rate limit, timeout, cache issue or session lock. For firmware 1.0.7.70, the controlled deployment procedure must initially enforce at least 300 seconds between Configure operations for the same phone. H8M validated two consecutive E2E cycles with that interval.

## Regression gates

Before changing the GXP1625 implementation, preserve all of these properties:

- OUI discovery remains functional.
- Binary cfg generation remains available.
- XML generation remains available and derives from the same P-value map.
- No secrets appear in logs/artifacts/argv.
- Endpoint-specific HTTP credential precedence remains intact.
- Native login yields a SID.
- Native provisioning POST yields success/right.
- Endpoint selection is exact and returns to zero.
- 202 remains registered from the expected phone IP after provisioning.
- No factory reset is required.
